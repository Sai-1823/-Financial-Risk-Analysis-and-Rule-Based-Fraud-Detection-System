5-person team · Advanced difficulty

## 🧭 Core rule

**Git is the source of truth. AI is a pair-programmer, not the architect.**  
Every line of code must be read, linted, tested, and approved by a human before it reaches `main`.

## 🌿 Git workflow

1. **Clone the repo**
   ```bash
   git clone https://github.com/Sai-1823/-Financial-Risk-Analysis-and-Rule-Based-Fraud-Detection-System.git
   cd "-Financial-Risk-Analysis-and-Rule-Based-Fraud-Detection-System"
   ```

2. **Sync with `develop`**
   ```bash
   git checkout develop
   git pull origin develop
   ```

3. **Create a feature branch** (one person, one branch)
   ```bash
   git checkout -b feature/data-schema     # example: Person 1
   # or
   git checkout -b feature/api-transactions # example: Person 2
   ```

4. **Commit regularly**
   ```bash
   git add .
   git commit -m "feat(schema): add customers and accounts tables"
   ```

5. **Push and open a Pull Request**
   ```bash
   git push origin feature/data-schema
   ```
   Then open a PR on GitHub: `feature/...` → `develop`.

6. **Review & merge**
   - At least one teammate must review and approve.
   - CI must pass (lint + tests).
   - Squash and merge into `develop`.
   - `develop` → `main` only at release points.

**Never push directly to `main` or `develop`.** Always use a PR.

## 🤖 AI usage policy

Because everyone uses a different AI, outputs will differ. Follow these rules:

- **AI-generated code must be reviewed by a human** before it is committed.
- **Run the linter and formatter** on every file an AI touches.
- **Write or verify at least one test** for every new feature.
- **Never commit secrets** (`.env`, API keys, DB passwords). Use `.env.example` only.
- **No real banking data.** Synthetic data only (see `data/` and acceptance criteria).
- **Document which AI was used** in the PR description (optional but recommended).

## 💻 Coding standards

- Language: Python 3.10+
- Formatter: `black`
- Linter: `ruff`
- Type checker: `mypy`
- Test framework: `pytest`
- API docs: OpenAPI/Swagger (auto-generated by FastAPI)

Install dev tools:
```bash
pip install black ruff mypy pytest
```

Run before committing:
```bash
black .
ruff check .
mypy app/
pytest
```

## 🧪 Testing

- Every feature needs tests in `tests/`.
- Run the full suite before merging:
  ```bash
  pytest
  ```
- CI runs on every PR and blocks merge if tests fail.

---

## 🔐 Secrets

- Create `.env` from `.env.example` locally.
- **Never commit `.env`.** It is in `.gitignore`.
- No production credentials in the repo.
